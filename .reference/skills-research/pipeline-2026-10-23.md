# Toghen pipeline map: from a repository to CSS, Figma and FigCraft

*Research for the Claude Code skills that run the pipeline. Read from `main` at figma 6.2.0, lib 5.1.0, postcss 0.20.0, query 0.1.0, ui 0.3.2, on 23 October 2026. The CLI, `check`, `members`, `toghen-query` and a CSS build were run on a synthetic system (section 8). The plugin and FigCraft paths were read from code and docs and were not run in this research. Every claim names its file. Paths are relative to the repository root.*

Synthetic names only: the example system is `mini`, its component is `Chip`. Nothing here names a consumer.

---

## 0. One page: the pipeline

```
repository (the only source)                          targets
──────────────────────────────                        ──────────────────────────────────────────
tokens/*.tokens.json  ─┐                               CSS            @toghen/postcss, in the DS's own build script
tokens/*.resolver.json ┼─ @toghen/lib load() ───────►  Figma file     toghen-figma ── ws://localhost:3055 ── Toghen plugin (desktop app)
--overrides map.json  ─┘        (bundle, Resolver)     FigCraft file  toghen-figma --figcraft <port> ── FigCraft control socket
components/*.component.kdl ─┐                          checks         toghen-figma check / members, toghen-query (no Figma)
docs/*.artboard.kdl  ───────┼─ read and checked by the plugin's reader (also in Node for check/members)
--input data.json  ─────────┘
```

- **One semantics.** `@toghen/lib` loads and resolves everything. The CSS adapter, the plugin and the FigCraft target all read the same `load()` output; none redefines a token.
- **One engine, three ways in.** The plugin's handlers and the component engine run inside the Figma plugin (paired over a socket), or in the CLI's own Node process against FigCraft's control socket (`cli/figcraft.ts`), or (checks only) in Node with no target (`cli/check.ts`, `cli/members.ts`).
- **One order, always:** load → check every file → variables → styles → component files → artboard files → end-of-run restack. `toghen-figma sync` does exactly this. Splitting it is possible but has traps (section 3).
- **Reconcile, never rebuild.** Everything Toghen writes is stamped (shared plugin data `toghen/stamp` in Figma; a `-toghen` divider page plus layer data in FigCraft). A second run writes only the difference; a designer's edit to a declared field is *drift*, kept and reported unless `--overwrite-drift`; a step that would break instances is *breaking*, refused unless `--allow-breaking`.
- **What needs a person:** opening Figma, importing and running the plugin, typing the pairing code once per plugin session, publishing a library and accepting its update, enabling a library, installing fonts, creating pages and files, swapping instances of removed members, deciding on `--allow-breaking` and `--overwrite-drift`, downloading an export. Nothing in Figma runs headless.
- **What runs anywhere (CI):** `toghen-query … check`, `toghen-figma check`, `toghen-figma members`, the CSS build with `onUnresolved: 'throw'`, the packages' tests.

## 1. The inputs

### 1.1 Token files (`*.tokens.json`)

- **Format:** W3C DTCG token documents: groups, tokens (`$value`, `$type` inherited from the group, `$description`, `$extensions`). Use the structured shapes: colour `{ "colorSpace": "srgb", "components": [r,g,b], "hex": "#…" }`, dimension `{ "value": 8, "unit": "px" }`, `fontFamily` as an array. References are `"{group.token}"` (no collection segment needed when the document has one collection).
- **Docs:** `toghen-lib/model.md` (tokens, groups, paths, parts), `toghen-lib/guide.md` (*Start from token files*), the W3C copies in `.reference/w3c-token-format/`.
- **Loaded by:** `load(entry, { read, name?, overrides? })` (`toghen-lib/reference.md`, *load*). A list of token files merges in order, last wins; the collection is named after the files' common folder unless `--name`/`name` is given (required when they share no folder).

```json
{ "space": { "$type": "dimension", "sm": { "$value": { "value": 8, "unit": "px" } } },
  "surface": { "$type": "color", "accent": { "$value": "{palette.blue}" } } }
```

### 1.2 The resolver document (`*.resolver.json`)

- **Format:** W3C Resolver, `"version": "2025-11-01"`, `name`, `description`, `sets` (named static layers of `sources`), `modifiers` (named choices: `contexts` → sources, `default`), `resolutionOrder` (required; later wins). `$ref` to files, to fragments (`file.json#/color`), to another resolver's sets/modifiers (an overlay). A file is a resolver when its `resolutionOrder` is an array.
- **Docs:** `toghen-lib/reference.md` (*The document: ResolverDocument*, *load*), `toghen-lib/guide.md` (*Load a resolver document*, *Theme a system with a map*, *Build on a base: an overlay*), `.reference/w3c-token-format/w3c-resolver.md`.
- **Toghen's requirements on top of the standard:**
  - **Every modifier needs a `default`.** The plugin and `check` build "the sum" (defaults, then each context alone) and refuse a modifier without one (`toghen-figma/guide.md`, *Load a token document*).
  - **Each modifier becomes one Figma collection, one mode per context.** At most **10** contexts for Figma per modifier (fixed for every plan), else the plan stops: `"theme" has 14 contexts for Figma and Figma allows 10 modes per collection; keep at most 10 of them in figma.include.`
  - A non-default context needs a CSS spelling (`css.selector`/`atRule`), or postcss reports `Cannot write context … Add $extensions["com.toghen"].css to the modifier.`
  - States are **parts** (subgroups), not modifiers. A modifier named `state` collides with the folded `state` axis (`toghen-figma/guide.md`, *Move a component file off state modifiers*).

```json
{
  "version": "2025-11-01",
  "name": "mini",
  "sets": { "base": { "sources": [ { "$ref": "vocabulary.tokens.json" }, { "$ref": "roles.tokens.json" } ] } },
  "modifiers": {
    "theme": {
      "default": "light",
      "contexts": { "light": [], "dark": [ { "$ref": "theme.dark.tokens.json" } ] },
      "$extensions": { "com.toghen": { "css": { "selector": "[data-theme='{context}']" }, "figma": { "include": ["light", "dark"] } } }
    }
  },
  "resolutionOrder": [ { "$ref": "#/sets/base" }, { "$ref": "#/modifiers/theme" } ]
}
```

### 1.3 The overrides map (`--overrides map.json`)

- One JSON object: a `$ref` **exactly as written** (fragment included) → the location to read instead, resolved against the document that holds the `$ref`. Applies in every document `load` reads. Unused keys are reported as warnings. `load` returns `overrides.hash` (FNV-1a 64) and `reads`.
- **Docs:** `toghen-lib/reference.md` (*The overrides map*), `toghen-lib/guide.md` (*Theme a system with a map*), `toghen-figma/guide.md` (`--overrides`). Example: `toghen-lib/example/warm.overrides.json`.
- Not the same map as Build's overrides in the plugin's lock (component name / token path / library name → name or `(key)"…"`; `toghen-figma/reference.md`, *The lock*). Same type, different use.

```json
{ "roles.tokens.json": "roles.warm.tokens.json" }
```

### 1.4 `$extensions["com.toghen"]` keys (the full roster found in code)

| Key | Where | Read by | Effect | Documented in |
|---|---|---|---|---|
| `css.selector`, `css.atRule` (with `{context}`), `css.contexts.<ctx>.{selector,atRule}` | a modifier | lib `getContextSelector`, postcss | How a context is spelled in CSS | `toghen-lib/reference.md` (*getContextSelector*), `toghen-lib/src/resolver/context-selector.ts` |
| `css.parts` = `{ axis: { value: spelling } }` | document root or any group | lib (`vocabularyAt`, `partsOf`, `axesOf`), postcss, figma | The parts vocabulary: which subgroup keys are parts. A holder below overrides one entry | `toghen-lib/model.md` (*The vocabulary*) |
| `css.parts: false` | a group | lib, postcss | The group is not a component (a lookup table); its subgroups are not parts | `toghen-lib/reference.md` (*Parts*), postcss guide (*Keep a lookup table out of the parts*) |
| `css.write: false` | a token | postcss | Keeps the token out of its group's mixin; still declared and readable with `t()` | `toghen-postcss/reference.md` (*css.write*) |
| `figma.include: [contexts]` | a modifier | figma (`main/utils/resolverModes.ts`) | Which contexts become modes (default must be in it; ≤10). Taking one out later is a breaking mode removal | `toghen-figma/guide.md` (*The mode limit*), `reference.md` |
| `figma.scopes: [VariableScope…]` | a token or group (nearest wins) | figma (`main/utils/purpose.ts`) | Which Figma pickers list the variable. `[]` hides it (still an alias target) | `toghen-figma/guide.md` (*Which fields a variable is offered to*) |
| `figma.value: "{ref}"` | a token's definition (per context) | figma (`main/utils/sum.ts`) | What Figma writes where CSS holds `currentColor`/`inherit`/an `em` letter spacing. Refused on a value Figma can hold | `toghen-figma/guide.md` (*A value only CSS can hold*) |
| `version: "x.y.z"` | a set or modifier | lib `getDeclaredVersion()` | The system's own version, shown in the plugin's Recents | `toghen-lib/reference.md` |
| `com.toghen.figma.stamp` | output only | plugin Export | Written by Export for reading; never read back | `toghen-figma/reference.md` (*Stamps on variables and styles*) |
| `generated: { of, modifier }` | output only | lib | Marks a token an adapter materialised | `toghen-lib/reference.md` |

Retired: `css.inherits: false` on a modifier (Figma never read it; states are parts now).

### 1.5 Component files (`<name>.component.kdl`)

- **Format:** kdlet (KDL + `guard`/`when`/`else`/`define`/`+call`). Toghen's top-level words: `component <Name> [tokens="{group}"] [layout=parts] [across="a, b"]`, `description`, `properties { VARIANT … | BOOLEAN … | TEXT … | INSTANCE_SWAP … | SLOT … }`, `exclude`, `include`; then exactly one root `FRAME`. Layer kinds: `FRAME`, `SLOT`, `TEXT`, `INSTANCE`, `LINE`. Fields spelled as the Plugin API spells them.
- **The value rule:** every bindable field takes a token reference `"{space.sm}"` or an explicit `(literal)8`; a bare number or colour is refused. `(property)Name` wires to a component property. `(key)"…"` names a published component. `(input)Axis` is an axis value.
- **From the tokens:** `component X tokens="{group}"` binds the root by CSS-keyed tokens (`backgroundColor`→fills, `paddingInline`→left/right, `borderRadius`→cornerRadius, `color`→text fill, `font`→textStyle…) and adds one variant axis per part axis the group's subgroups use (`rest` first). Folded axes become Figma collections of modes, pinned per member; `layout=parts` keeps one variable per part.
- **Docs:** `toghen-figma/component-files.md` (the format, complete), `toghen-figma/guide.md` (*Write a component file* onward), `toghen-figma/reference.md` (*Component files*, *run*). Fixtures: `toghen-figma/test/components/fixtures/*.component.kdl`, `toghen-figma/test/example/button.component.kdl`, `toghen-figma/test/fixtures/figcraft/*.kdl`.

```kdl
component Chip tokens="{chip}"
description "A compact label on the accent colour."

properties {
    TEXT Label default="Chip"
}

FRAME Chip layoutMode=HORIZONTAL layoutSizingHorizontal=HUG layoutSizingVertical=HUG counterAxisAlignItems=CENTER {
    TEXT Caption tokens="{chip}" characters=(property)Label textAutoResize=WIDTH_AND_HEIGHT
}
```

### 1.6 Artboard files (`<name>.artboard.kdl`) and their data (`--input`)

- **Format:** the component format with `artboard <Name>` instead of `component`; no properties/axes/members; `each x in=(input)list key=field { … }` repeats over a list; `set Name=(x)field` on an `INSTANCE`; `slot Name { … }` fills an instance's slot. Refused there: `tokens=`, `(property)`, `isExposedInstance`, `SLOT` layers, `description`.
- **Data:** `--input <doc>` is a resolver-like document; resolved at default contexts; tokens nested by path; a token whose `$value` is a list of flat records is a list. One `--input` per run.
- **Docs:** `toghen-figma/component-files.md` (*Artboard files*), `toghen-figma/guide.md` (*A documentation page from the repository*), `toghen-figma/shared/inputs.ts`, `toghen-figma/test/inputs.test.ts`.

```kdl
artboard "Chip reference"
FRAME Page layoutMode=VERTICAL itemSpacing="{space.sm}" {
    fills "{surface.page}"
    TEXT Title characters=(input)title textStyle="{type.label}"
    each c in=(input)examples key=label {
        INSTANCE Example component=Chip { set Label=(c)label }
    }
}
```

```json
{ "version": "2025-11-01", "name": "chip-docs",
  "sets": { "base": { "sources": [ { "title": { "$value": "Chip" },
    "examples": { "$value": [ { "label": "Default" }, { "label": "Selected" } ] } } ] } },
  "resolutionOrder": [ { "$ref": "#/sets/base" } ] }
```

### 1.7 Blueprints (`<page>.blueprint.kdl`): read, not runnable from the CLI

`page`, `tokens`, `library`, `component … { }` and `artboard … { }` bodies in one file (`toghen-figma/component-files.md`, *Blueprints*). The plugin's Build pane keeps one and lists its needs; **building a blueprint as a whole, and from the command line, is not built** (`toghen-figma/specs.md`, *Blueprints*, *Not built yet*). A pipeline must pass the component and artboard files individually.

### 1.8 Conventions files (`*.conventions.json`)

- A JSON array of `{ id, pattern, property, nodeTypes, variableType, description? }`, `pattern` with `{component}` and `{variant}`. For files whose variables were made by hand or by another tool; a file built by variable sync and component files needs none.
- **Plugin screen only** (Apply pane: Audit, Scaffold, Bind). No CLI command, and refused in FigCraft (`Binding layers is not built for FigCraft yet`, `cli/figcraftFile.ts`).
- **Docs:** `toghen-figma/guide.md` (*Bind layers by convention*), `toghen-figma/reference.md` (*Conventions JSON schema*). Fixture: `toghen-figma/test/fixtures/sample.conventions.json`.

|---|---|---|

| positional `*.kdl` | components, sync, check, members | Component files run first, then `*.artboard.kdl`, whatever the order given |
| `--resolver <entry.json>` | components | Loads the design system into the plugin (for `tokens=`, `(modifier)`, unbindable values); syncs nothing |

| `--overrides <map.json>` | all but lock | The `$ref` map |

## 3. The order, and what must be open

### 3.1 The order a full sync follows (`cli/run.ts`, `runSteps`)

1. **Read from disk** (CLI): `load` the entry, read every `.kdl`, read `--input`. Unreadable file → exit 1 before listening.
2. **Reach the target:** pair with the plugin on `ws://localhost:3055`, or connect to FigCraft's control port.
3. **Load and check, nothing written:** `LOAD_DOCUMENT` (the plugin re-runs the same `load`; collisions and unused map keys print as `warning:`/`note:`), then `CHECK_COMPONENTS` (each file read, evaluated, checked; with `sync` every token/style name held against the design system; stamped sets Figma reports broken; strays). Any problem → exit 1.
4. **Variables:** `PLAN_VARIABLE_SYNC` → print → stop on a `stops` warning (base collection built by an older sync, modifier without default) → stop on breaking without `--allow-breaking` → `EXECUTE_VARIABLE_SYNC`. Any failed operation stops the run.
5. **Styles:** `PLAN_STYLE_SYNC` (same `collectionName`) → `EXECUTE_STYLE_SYNC`.
6. **Dry run only:** `GET_FIGMA_COLLECTIONS`, then `pendingNames()` over both plans → `RunOptions.pending`.
7. **Each component file, then each artboard file**, one at a time: `RUN_COMPONENT`.
8. **End of run, once:** `FINISH_COMPONENTS` (remove strays with `--allow-breaking`; restack Toghen's sets and artboards on each touched page, 100 px apart).
9. **Exit**; the plugin stays open and reconnects to the next run by itself.

**Why this order.**
- **Variables before styles:** a style's members (font size, shadow colour) bind to variables; without them the style plan writes values and warns.
- **Styles before components:** a component's `textStyle`/`effectStyle` resolves to a style by name; tokens resolve to variables named `tokenPathToVariableName(path)` (`space.sm` → `space/sm`), searched across every local collection; a name found nowhere or twice stops the run before writing.
- **Check before variables:** the check tells the variable plan which components use `layout=parts` (kept per loaded resolver, `main/utils/folds.ts`). A sync that never checked folds everything, and a `layout=parts` file then fails with `names no variable`. **So use `sync`, not `variables` followed by `components`, when any file has `layout=parts`.**
- **Components before artboards:** an artboard instantiates components. `pending` covers variables, text/effect styles and modes, **not components**, so the dry run of a first-ever sync cannot plan an artboard that instances a component the same run would create. First build: dry-run and run the component files; then dry-run and run with the artboards.
- **Library before target:** the target's lock holds the library's keys; a key imports only after a person publishes the library and accepts the update in the target.
- **Dry run first:** there is no rollback (`figma.triggerUndo()` was measured reverting past the last commit, `.reference/figma/measured_behaviour.md` §8). The engine refuses before its first write everything it can foresee; a Figma refusal mid-run leaves partial writes that the next run completes. The dry run is where breaking steps, drift, pending names, font fallbacks, ambiguities and FigCraft refusals are read.

### 3.2 What each step needs open or running

| Step | Needs |
|---|---|
| Any CLI command | A Toghen checkout with `pnpm install` and `pnpm build` (root `pnpm -r build` builds `@toghen/ui` before `@toghen/figma`, which inlines `@toghen/ui/styles.css`). A current Node first on `PATH` (developed on 25; an old one fails silently). In a dependent repo: `@toghen/figma` as a **linked checkout** (private package; its bin needs `tsx` and `esbuild` from the checkout) |
| `check`, `members`, `toghen-query`, CSS build | Nothing else. CI-safe |
| Figma `variables`/`components`/`sync` | Figma **desktop** app (browser not measured); the plugin imported from `toghen-figma/dist/manifest.json` (Plugins → Development → Import plugin from manifest…), **built from the same checkout as the CLI** (no version check between them); the target file open; the plugin running in it; paired (code typed under the Load pane's **Source** card, **Connect**); port 3055 free; every page named by `--page` existing; fonts used by text styles installed or shared where Figma runs |
| `--library` runs | Both files open in the desktop app, the plugin running in **each**, two codes typed, one per file; the library name exactly as Figma shows it; afterwards a person publishes and accepts the update |
| FigCraft runs | FigCraft started with `--control <port>` (`open -a FigCraft --args --control 7979`; a second instance with `open -n -a …` so a person's open instance is left alone; wait for `nc -z 127.0.0.1 7979`); the target file **shown in the front window** when the run starts; pages named by `--page` existing; fonts listed by `text.fonts` (FigCraft's faces are static instances), including **Inter Regular** for any component with text; no other program driving that FigCraft instance |

## 4. Automatic, and what needs a person

### 4.1 Automatic

- Loading (with `$ref`, overrides, collisions), checking, the order, the dry-run `pending` names, the restack, stamping, drift detection, the copy rule (a person's duplicate keeps no claim), stray detection, axis renames (one name changed, same values), relinks when the lock sends a name to another key.
- **Reconnecting.** The code is kept in `~/.toghen/figma-pairing` (dir `0700`, file `0600`; the library's beside it with `.library`). A new run waits 3 s for the plugin paired earlier, which retries every second, so **after the first pairing, later runs need nobody** as long as the plugin stays open.
- FigCraft: no pairing; the run pins the shown file and re-shows it in every batch; one undo step per operation, plus one `Toghen stamps` step.

### 4.2 Needs a person (or an agent with explicit delegation)

- **Pairing, once per plugin session.** The CLI prints `Pairing code: XXXX-XXXX` and waits **with no limit**. The code goes into the plugin's Load pane → Source card → field *Code from toghen-figma* → **Connect**. Closing the plugin, or rebuilding and reopening it, ends the pairing; the next run prints a new code. (The CLI's printed hint says *"under "Command line" on its System pane"*; there is no System pane. See section 7.)
- Opening Figma, importing the plugin, opening the file, running the plugin; creating files and pages.
- **Not touching the plugin during a run:** the CLI takes the first response of the type it expects, so a button pressed at the screen can be mistaken for the run's answer (`toghen-figma/decisions.md`, *Open questions › The command line*).
- **Libraries:** publish in the library file; enable the library and accept its update in the target (Figma's assets panel). A plugin can do none of these.
- **Decisions:** `--allow-breaking` (instances of a removed member keep pointing at it and must be swapped by someone; Figma keeps the removed component off-page) and `--overwrite-drift` (throws away designer edits, all or nothing).
- **Unblocking refusals:** a set of the component's name that Toghen did not make (rename/delete it); a set Figma reports broken (delete or rename the named members); two sets stamped as one.
- Installing fonts; downloading an Export.

### 4.3 CI

- No plugin runs headless; the REST API cannot write file contents and its variables endpoints are Enterprise-only (`toghen-figma/specs.md`, *Why there is no Figma sign-in*, *Not in this design*). CI can run: `toghen-query --doc … check` (parse the output), `toghen-figma check`, `toghen-figma members`, the CSS build with `onUnresolved: 'throw'`, `pnpm test`. FigCraft needs a running app with a shown file; a CI machine with a display was not tried.

### 4.4 What a dry run proves, and what it does not

| Proves | Does not prove |
|---|---|
| Every file reads and checks; every token/style name resolves in the file or in `pending`; no name is ambiguous (as of now) | That a published key imports (a dry run imports nothing) |
| The variable and style plans: creates, updates, skips, drift, breaking steps, the mode limit, the stop conditions, scope notes | Artboards instancing components the same run would create |
| The font each text style would take (fallback lines, skipped styles) on **this** machine | That Figma accepts every write (a mid-run refusal leaves partial writes) |
| Each component's steps, breaking lines, drift (`left:`), pending lines; strays; broken sets | A `--collection` ambiguity that only appears once two collections both exist |
| FigCraft: every field/kind not built there (`refuses` runs on dry runs too) | FigCraft: hand edits to a layer's property wiring or pinned modes (not reported by FigCraft; trusted) |
| An older build's root record migrated in memory only | The look. Compare by eye or screenshot |

### 4.5 Drift, `--overwrite-drift`, `--allow-breaking`

- **Drift** = a field Toghen owns whose stamp receipt no longer matches what Figma reports, and the source's value does not match either. Kept, reported every run (`drifted: <path> — <message>` for variables/styles; `left: … "paddingTop" was changed in Figma since Toghen wrote it` for components), never overwritten without the flag. A value Figma moved to exactly what the source now asks for is re-stamped silently. A field the file stops declaring keeps its value and is reported once.
- **`--overwrite-drift`**: writes the source's value, scopes and style fields over every drifted one, and the file's value over every drifted component/artboard field (`OVERWRITE` warnings). All or nothing; the plugin screen never offers it.
- **`--allow-breaking`**: lets a real run take steps flagged `breaks`. Without it: the **variable** gate stops the whole run before writing (`Variable sync will not run: N step(s) would lose something in Figma, and nothing was written; pass --allow-breaking to take it`); **strays** stop the run at the check; a **component's** breaking steps stop that component (`<file>: was not built: …`), the run continues with the next file, exit 1. A dry run lists all of them and exits 0.

### 4.6 What stops a run (nothing written unless said)

- CLI argument errors; an unreadable file; an entry that does not load.
- Port 3055 taken; five wrong pairing codes; the plugin closing mid-run (`the plugin disconnected: it was closed, or Figma lost it`; earlier writes stay).
- Any check problem (file errors, names not in the design system, broken stamped sets, strays without `--allow-breaking`).
- A variable plan `stops` warning; breaking variable steps without the flag; a failed variable or style operation (stops before components).
- Per component: unresolved or ambiguous names, a foreign set of that name, two stamped sets, breaking steps without the flag, a missing page, FigCraft refusals.
- FigCraft: nothing on the port; no file shown; the pinned file leaving its tab (later batches refused unsent).

## 5. Assets: images, icons, fonts

### 5.1 What Toghen does today

| Asset | CSS (`@toghen/postcss`) | Figma / FigCraft (component files, styles) |
|---|---|---|
| **Font families** | Writes `font-family` stacks from `fontFamily` arrays (and `font` shorthands with `typography: 'font'`). Writes **no `@font-face`** and embeds nothing | A text style takes the **first family in the stack listed by the target with the style asked for** (`main/utils/fontStack.ts`); generic names are passed over; the plan says what it passed over (`"…" uses "Menlo": "ui-monospace" and "SFMono-Regular" are not available in Figma.`); a style whose families none load is skipped, the rest goes on. The face is the typography's `fontStyle` member (default `Regular`, `main/utils/figmaStyleAdapter.ts`); the weight is a separate field, bound to a variable in Figma, **not bound in FigCraft** (that style is rewritten every run). Any component with text loads **Inter Regular** (`main/components/apply.ts`, `DEFAULT_FONT`) |
| **Icons as an icon font** | Nothing in Toghen. The one real design system here generates `.ph-<name>::before { content }` rules and embeds the font as a data URI in **its own** build script (`toghen-ui/scripts/build.mjs`, `toghen-ui/src/icons.js`) | Expressible, not exercised: a `TEXT` layer whose `characters` is the icon's code point (plain text, or a `string` token bound to it) and whose `textStyle` is a typography token in the icon face. The face must be installed or org-shared wherever Figma opens the file, and listed by FigCraft. The ruling that an icon in Figma is such a text layer, and that this must be checked before an icon component is built, is open in `toghen-ui/decisions.md` (*Questions the reflection raises*, *The icon font's cost*) |
| **Icons as vectors / SVG** | Nothing | **No vector layer kind** (only `FRAME SLOT TEXT INSTANCE LINE`). An icon must already be a component in the file (or a published one, by `(key)"…"` in Figma only), and component files instance it: `INSTANCE Mark component=Icon`, `INSTANCE_SWAP Icon default=Icon`. A component Toghen did not make can be instanced; a **set** of a component file's own name that Toghen did not make blocks that component file |
| **Images (raster)** | Nothing beyond what a token value holds | **Not supported**: no image paint in component files; a `background` key holding an image is skipped into the notes; paint styles are gradients only |
| **Gradients, shadows** | Written | Gradient and shadow tokens become paint/effect styles, and `fills`/`effects` fields in Figma; **refused in FigCraft components** (gradient fills, effects as fields) |

### 5.2 What a pipeline must do outside Toghen

1. **CSS fonts and icon fonts:** add `@font-face` (or embed `woff2` as data URIs, as `toghen-ui/scripts/build.mjs` does by replacing `url(PLACEHOLDER)` after the PostCSS pass) and any icon-glyph rules in the design system's own build.
2. **Figma fonts:** install every family/face the typography tokens name on the machine running Figma (or share it through the organisation); read the style plan's fallback and skip lines in the dry run.
3. **FigCraft fonts:** confirm each face with `text.fonts {family}` (FigCraft lists static instances: a weight with no named instance has no exact match).
4. **Vector icons and images, before Toghen runs:**
   - Figma: create them as components through another route (a person; a library; the Figma MCP connector's `use_figma` with `figma.createNodeFromSvg` / `figma.createImage`, which is outside Toghen and writes no stamps). Name them as the component files name them.
   - FigCraft 0.9.0 (`.reference/skills-research/figcraft-commands-0.9.0.txt`): `file.import {path}` turns an SVG into an editable frame; `image.place {path, parent, mode}` makes an image layer; `component.create` turns a frame into a component; `page.add {name}` makes the pages `--page` needs; `file.new {name}` and `file.save {path}` create and save files.
5. **Publish icon libraries** in Figma by hand if target files use them by key; FigCraft has no libraries in this design.

## 6. Failure modes and their messages

Format: what the agent sees → what it means → what to do.

### 6.1 CLI and arguments (`cli/main.ts`, `cli/run.ts`)
- `no entry given: a resolver document or token files (.json)` → add the `.json` entry.
- `components takes the design system with --resolver; X is not a component file` → use `--resolver X`, or `sync`.
- `variables takes the entry and nothing else; sync runs component files too` / `no component file given; variables syncs the tokens alone`.
- `--input is read only when an artboard file (<name>.artboard.kdl) is among the files; none is`.
- `--library and --figcraft do not go together: FigCraft has no libraries to publish or import from`.
- `--figcraft takes the port FigCraft's control socket listens on, a number; got …`; `unknown option --x for <cmd>`; `--x needs a value`.
- `--overrides <file> cannot be read as JSON: …` / `must hold one JSON object: …`; `<file> cannot be read: …`.
- `<entry>: $ref "…" in "…" …` → lib's `InvalidReferenceError` from `load` (URI scheme, unreadable/non-JSON file, pointer to nothing, cycle, token files with no common folder and no `--name`…).

### 6.2 Pairing and the socket (`cli/bridge.ts`, `ui/components/pane-load.js`)
- `Pairing code: ABCD-2345` then `Waiting for the plugin on ws://localhost:3055…` → a person types the code in the plugin; the command waits forever (Ctrl-C stops it).
- `Looking for the plugin paired earlier on ws://localhost:3055…` → normal; 3 s grace, then a new code.
- `In the library file "<name>", enter …; in the target file, enter …` → two codes, one per file.
- `The plugin is paired.` / `Both plugins are paired.` → proceed.
- `port 3055 is taken: another toghen-figma, or another program, is listening on it…` → one run at a time; stop the other.
- `5 connections gave a wrong pairing code, so the run stopped. Something other than the plugin is using port 3055`.
- `the plugin disconnected: it was closed, or Figma lost it` / `the plugin is not connected` → rerun; earlier writes stay and the next run completes them.
- Plugin screen: `Nothing answered on localhost:3055 (tried at …). Run toghen-figma; this keeps trying.`; `The command line did not accept that code (…). Type the one it printed.` (a code from before the plugin closed).

### 6.3 Checks (`toghen-figma check`, and step 3 of a run): `<file>:<line>:<column> <message>`
- `token {space.xl} is not in the design system "mini"` → typo or a token not defined; fix the file or the tokens.
- `"width" takes a token reference or a (literal) number, or #null: a bare 12 would be a number nobody chose, write (literal)12 or a token reference`.
- A field beside `textStyle` that the style also sets; `tokens` on an `INSTANCE`; `(property)` in `set`; `each` in a component file; a `when` outside a layer; duplicate addresses; grid rules: each refused with its line (`component-files.md`, *What is checked*).
- `component tokens="{nothing}" names no token and no group of the design system`.
- `VARIANT "State" takes its values from the modifier "state", which the design system does not have`.
- `… is not one Figma gets` → a context left out of `figma.include` named in an axis, `exclude`, guard or `modes`.
- `breaking: "<name>" (<id>) is a member outside any set, left by an earlier run; it is removed with --allow-breaking.`
- Broken stamped set: the members at fault with ids, `ours`/`made by hand`, ending `delete or rename the members named, then run again`.
- Summary on stdout: `N files read: no errors` or `N files read: K errors[, M warnings]`. Warnings (`warning:`) never fail: the usual one is a property wired to nothing in a member.

### 6.4 Variable and style plans (CLI prints `Variable plan: … creates · … updates · … skips[ · modes · scopes · drifted · warnings · breaking]`)
- `Variable sync stopped, so nothing was written and no style or component was run.` after a warning such as `Collection "<name>" was built by an earlier sync: it holds mode(s) …` (rename/remove that collection) or a modifier with no default.
- `"theme" has 14 contexts for Figma and Figma allows 10 modes per collection; keep at most 10 of them in figma.include.`
- `The part axis "state" folds into a collection of that name, and the base collection or a modifier already has it. …` → rename the axis or `layout=parts`.
- `Variable sync will not run: N step(s) would lose something in Figma, …; pass --allow-breaking to take it` with `breaking: the mode "<ctx>" of collection "<m>" is gone`.
- `drifted: <path> — <modes that moved>` → a hand edit in Figma; kept.
- `skipped: "<path>" is currentColor, which Figma cannot hold; skipped.` / `… is a letter spacing in em …; skipped.` / `… is defined only in theme=dark and has no value where theme=light, the default; …` → add `figma.value`, or define a default.
- `note: N variables are offered to every field: …; declare figma.scopes to narrow them.`
- `"<style>" uses "<family>": "<a>" and "<b>" are not available in Figma.` → font fallback on this machine.
- `"<component>": "<axis>" stays in the path, one variable per part: no rest value: "<x>" needs "<y>", which is not defined.` → informational fold decision.
- `Collection "state" holds variables this document wrote, but nothing in the document is named "state" any more … It is left alone.`
- Execute: `Variable sync: A applied · S skipped[ · F failed]`; with failures `failed: <reason>` and `Variable sync did not complete, so no component was run.`

### 6.5 Component and artboard runs: `<Name>[ (dry run)]: N steps · c created · u updated · d deleted[ · b breaking]`, then lines `pending:`, `breaking:`, `warning:`, `left:`
- `<file>: was not planned|built: <headline>` then `  - <problem>` lines:
  - `token {space.xl} names no variable in this file: looked for "space/xl"; run the variable sync first` (or a `layout=parts` file after a folded sync, or `components` without `--resolver`).
  - `token {x} is ambiguous, 2 variables in this file are named "x/y"` → two base collections (inconsistent `--collection`) or a hand-made duplicate.
  - `component "Icon" (line N) is not in this file` → create/import it first.
  - `a component set named "Chip" already exists (ids) and Toghen did not make it; rename or delete it, or build on a page where it is not. Toghen never adopts a set by name`.
  - `no page named "Docs" in this file`.
  - breaking lines such as `the member "state=pressed" is gone: instances of it lose their variant`.
  - `token ds.x in member "…" is bound to opacity but is not an opacity; declare figma.scopes ["OPACITY"] on it`.
  - `<what>: <from> did not import: not published, or not this key: publish the library, then accept its update in this file`.
- `pending: token {space.xl} (line 12): the variable sync would create "space/xl"` → fine in a dry run.
- `left: … "paddingTop" was changed in Figma since Toghen wrote it, and was left as it is` → drift.
- `left: … is a copy of Toghen's …, left alone` → a person's duplicate.
- End of run: `removed "x" (id)`, `moved "Chip" to 0, 7381`, `note: …` (a set moved by hand that overlaps something).

### 6.6 FigCraft (`cli/figcraft.ts`, `figcraftFile.ts`, `figcraftApply.ts`, `figcraftRecord.ts`)
- `Nothing answered on 127.0.0.1:<port>: … Start FigCraft with --control <port>.`
- `FigCraft shows no file: open the file to sync into, then run again.`
- `Writing into "<file>" in FigCraft on port <port>.` → the pinned target.
- `FigCraft no longer has "<file>" at the tab it was in (a tab before it closed?): nothing more is written, and the step before this may have gone to "<other>".` → undo that step in the other file.
- `will not build "<component>": nothing was written` + `"<component>" <address>: the field <name> is not built in FigCraft yet` / `a LINE|SLOT layer is not built in FigCraft yet` / `a grid layout …` / `a gradient in fills …` / `a corner written as a value beside a cornerRadius token …` / `a component named by its key is not built in FigCraft, which has no libraries here` / `a SLOT property …` / `the default of "<p>" is a token, which FigCraft does not bind to a property yet`.
- `FigCraft does not list <family> <style>` → font missing in FigCraft.
- `FigCraft target: an effect style of <type> is not translated.` / `… a paint style of <type> is not translated.`
- `The default mode "<m>" of collection "<c>" is never deleted.`
- `The FigCraft target does not offer figma.<name>.` → a handler asked for an API the FigCraft view lacks (a bug or an unsupported command).
- `The stamps were not written into FigCraft: …. The next run adopts what this one wrote by name.`

### 6.7 Libraries (`cli/run.ts`, `copyKeys`)
- `Library "<n>": C components · S styles · V variables · file key … | no file key (only a private or development plugin reads it)`.
- `"<set>" is not published as it is now (UNPUBLISHED|CHANGED): publish the library, then accept its update in the target file.`
- `Dry run: the lock in the target file was not written.`
- `The lock in the target file was not written: the build in the library file did not complete.`
- `The lock in the target file holds "<n>", written by the build|command line.`

### 6.8 CSS (`@toghen/postcss`)
- `@toghen/postcss needs its options: it has no design system to read. Pass { system } …` (listed bare in a config).
- `Cannot resolve token "ds.x": Token 'x' not found in collection 'ds' for mode 'light/regular'.` (typo; with `onUnresolved: 'throw'` it stops the build).
- `Cannot write context '<c>' of modifier '<m>': the resolver document gives it no CSS selector. …`
- `Cannot write the mixins of "ds" inside a layer: …` (put `@toghen mixins;` at the top level).
- `"a.b" and "a-b" are both written as the mixin --a-b. …`; `Cannot write the mixins of "<group>": Path '…' nests two parts of axis …`.
- Every `@apply` left in the output → the mixins polyfill is listed before Toghen.
- Leak check after a build: no `[object Object]`, no unresolved `t(`/`toghen(` in the output (CLAUDE.md, *Testing*).

### 6.9 `toghen-query`
- One line per answer, last line `— <export>`. `error: <core message>` is an answer (exit 0). `check` prints `incomplete:`, `holes:`, `non-factorable:`, `collisions:`, each `(none)` when clean: **parse it; the exit code does not tell**.

## 9. The ten things an agent most often gets wrong

1. **Blocking on pairing.** A Figma-side `toghen-figma` run waits for the plugin with no time limit. Run it in the background, watch for `Pairing code:` and `The plugin is paired.`, and hand the code to the person. Do not look for a "System pane": the field is in the Load pane's Source card. After the first pairing, later runs reconnect alone while the plugin stays open.
2. **Splitting `variables` and `components` when a file uses `layout=parts`,** or running `components` on `tokens=` files without `--resolver`. The fold is learned from the check inside `sync`; split runs produce `names no variable`. Default to `sync`.
3. **Trusting a first-ever dry run with artboards.** `pending` does not cover components; an artboard that instances a component the same run creates fails its dry run. Dry-run and run the components first, then the artboards. A dry run also never imports a key.
4. **Reaching for `--allow-breaking` or `--overwrite-drift` to get a green run.** The first breaks instances in other files, and someone must swap them. The second throws away designer edits, all or nothing. Both are a person's decision after reading the dry run's `breaking:` and `drifted:`/`left:` lines.
5. **Writing to Figma another way.** No `use_figma` scripts, no REST, no hand-made sets named like a component file (Toghen never adopts by name and stops), no editing or copying stamps, no deleting and rebuilding a set (its key changes and every instance breaks). Toghen writes only through the plugin or the FigCraft socket, and reconciles in place.
6. **Changing `--collection` between runs, or omitting it on one run.** A second base collection duplicates every base token, and every later component build stops on `is ambiguous`.
7. **Assuming Toghen creates files, pages, fonts, icons or images.** `--page` must name an existing page. Fonts must be installed (Figma) or listed (FigCraft, Inter Regular included). Vector icons and images must already be components in the file. Read the style plan's fallback and skip lines.
8. **Writing component files loosely.** Use a bare number or colour and the run is refused: write `(literal)` and a reason comment, or a token. No field a text style also sets may stand beside `textStyle`. No `tokens=` on an `INSTANCE`. No `(property)` inside `set`. No `each` in a component file. Token references never name the collection, and Figma variable names use `/` (`space.sm` is `space/sm`). Run `toghen-figma check` after every edit.
9. **Misreading exit codes and outputs.** `toghen-query` exits 0 even when `check` lists holes or collisions, so parse its output. `toghen-figma check` cannot see the Figma file: existence and ambiguity are the dry run's. A failed component does not stop the other components (exit 1 at the end). A dry run exits 0 with breaking steps listed.
10. **Expecting FigCraft to match Figma.** Libraries, keys, slots, lines, grids, gradients and effects as fields are refused before any write. Weight-bound text styles are rewritten every run. Hand changes to wiring or pinned modes go unseen. Only one program may drive an instance, so do not use the agent's own FigCraft session alongside a run. Closing a tab before the target moves the target and stops the run.

Close runners-up: running two `toghen-figma` runs at once (port 3055); a plugin built from another checkout than the CLI (no version check), or rebuilt without reopening (new code needed); clicking in the plugin during a run; more than 10 contexts in a modifier, or a `figma.include` without the default; removing a context and expecting it to be quiet (it is a breaking mode removal).
