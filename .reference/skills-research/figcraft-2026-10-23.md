## What changed since 0.6.0

Only what an agent or Toghen meets; each release also carries many UI, `.fig` import, translation and packaging fixes.

**0.7.0 (18 Oct)**
- `command.batch` steps can reference ids made by earlier steps (`{"$step": n}`, `{"$step": n, "field": "…"}`), also when attached. The 0.6.0 failure the personal skill works around is gone.
- `figcraft-cli run` scripts are one undo step and resolve `$step`, exactly like `command.batch`.
- The control socket answers while a window is hidden or minimised (every window, not only the main one); a line that is not JSON ends the connection.
- `--automation-read-root` / `--automation-write-root` for the app and `figcraft-cli mcp`.
- A failed batch keeps the redo steps; failed commands roll back during interactions too.
- `variable.createCollection` refuses a name already taken (#416); `variable.update {scopes: null}` resets to all scopes.
- `node.set` refuses auto layout keys on non-frames, and font styles the family lacks.
- Negative or fractional indexes refused in `doc.switch`, `page.select`, `effect.set`, `fill.set`, `stroke.set`, `export.*`.
- `.fig` import: component slot content, grid track sizes, instance overrides by key, and much more.

**0.8.0 (20 Oct)**
- **`node.get` reports layer data (`pluginData`), pages included (#879).** This is what Toghen's stamps rest on.
- **An explicit edit detaches the variable bound to what it changed:** paints (`node.set fills`, `fill.set`…) and scalar fields (#809). Removing auto layout drops its gap and padding bindings (#810).
- **Effects refuse keys they don't read** instead of dropping them (the personal skill's `offsetX` trap now errors).
- A bound colour variable's alpha applies once, not squared (#802).
- Instances follow the variable modes their main component sets; duplicating, Alt-dragging or copy-pasting a main component in its file makes an instance (#892).
- `variable.import` reads `variables` outside `meta` and warns when it imports none (#790).
- A refused slot edit names `component.makeSlot`; `.fig` imports keep component property bindings.
- The app refuses unknown command-line options; `--control=PORT` works; CLI `info/export/convert/render/run` take the automation roots.
- Tabs can be reordered (`file.moveTab`), and the active tab is kept: a tab's index is not stable.
- New: `text.missingFonts`, `text.rescanFonts`, `text.loadFont`, `text.refit`, `pref.uiScale`, `pref.startOnHome`, `arrange.reorder`.

**0.9.0 (21 Oct)**
- Combine as variants from the context menu and the Design panel; *Add variant* on a lone component (#903). New sets are named from the variant path, not the first property.
- A document dropped on the canvas opens as a new file. FreeBSD aarch64 builds dropped.

**0.10.0 (22 Oct)**
- Security (HTTPS on downloads), CI pinning, README icon, `chrono` for UTC. No change to commands, protocol or docs.

## Conventions and gotchas an agent must know

From `mcp.md` *Conventions agents must know* and `control-protocol.md`, plus what the live run found (marked *measured*).

**The protocol**
- Socket: `127.0.0.1:<port>` only; newline-delimited JSON `{id, method, params}` → `{id, ok, result | error}`, in order. Requests run on the UI thread at the next frame; 60 s timeout; at most 8 connections and 8 queued requests (`control request queue is full`); 32 MiB per line.
- Methods: `engine.execute {command, params}` (any command), `engine.commands {}` (the list: `[{id, label, params, menu, shortcut, undoable}]`), `document.inspect {depth?, allPages?}`, `node.get {id, depth?}`, `window.list`, `window.new`, `window.focus`, `ui.inspect`, `ui.set`, `ui.pointer`, `ui.key`, `ui.type`, `ui.input`, `ui.menu.invoke`, `ui.screenshot`, `ui.render`, `app.quit`.
- **Every method takes `window`**; without it a request goes to the window last in front. `engine.execute` acts on **the file that window shows**: pin it with `doc.switch {index}` inside the same `command.batch`, and check the tab's name and path with `doc.list`, since tabs can be closed or reordered by hand.
- A minimised window still answers everything except `ui.screenshot`, `ui.input` and `window.new`; `ui.render` works without a window.
- MCP: `figcraft-cli mcp` (headless, an in-process session) or `--attach <port>`; tools `list_commands`, `run_command`, `batch`, `create_node`, `set_properties`, `get_node`, `inspect_document`, `screenshot`, `export`, `open_file`, `save_file`, `undo`/`redo`, `pointer`, `key`, `type_text`, `inspect_ui`. Attached calls are never replayed after a transport failure: inspect before retrying.

**Batches and undo**
- `command.batch {label?, commands}` is one undo step, all-or-nothing, undone whole when a step fails. `{"$step": n}` is step n's `id` (zero-based), `{"$step": n, "field": "f"}` another field; any object with a `$step` key is a reference, even inside plugin data or a variable value. A nested `command.batch` keeps its own references.
- *Measured:* `file.save {path}` and `library.publish` run inside a batch. Programmatic saves need a path the first time; dialogs never open.

**Coordinates and layout**
- Page units, y down; `x`/`y` relative to the parent frame (groups have no space of their own). Auto layout children are placed by the layout: set `layout`, `gap`, `crossGap`, `padding`, `mainAlign`, `crossAlign`, `sizingH`/`sizingV`, not x/y.
- `strokesIncluded` defaults to true on new auto layout: an inside stroke takes room like padding.
- Grid layout: `layout: "grid"`, `gridColumns`, `gridRows`, `gap`/`crossGap` (alias `columnGap`/`rowGap`), `columnTracks`/`rowTracks` as `[120, "1fr", "auto"]`, children `gridColumn`, `gridRow`, spans, `gridAlignH/V`.

**Paints, styles, variables**
- Colours `#RRGGBB(AA)`; gradients accept the shorthand `{type: "linearGradient", stops: ["#hex", …], from?, to?}` and read back as `{type: "gradient", kind, stops: [{color, position}], from, to, width}`.
- Lists (fills, strokes, effects, grids) are **bottom first**: index 0 paints first.
- Binding fields (`variable.bind {ids, field, variable}`): `fill`/`stroke` (first paint), `fills/<i>/color`, `fills/<i>/stops/<j>/color`, `effects/<i>/<offsetX|offsetY|radius|startRadius|spread|color>`, `layoutGrids/<i>/<size|count|gutter|offset>`, `componentProperties/<name>`, and the scalar fields (`width`, `height`, `opacity` in percent, `cornerRadius`, corners, `gap`, `crossGap`, paddings, stroke weights, `characters`, `visible`, text fields). Bindings follow their items when lists are reordered.
- **An explicit edit of a bound field detaches its variable** (0.8.0). Write literals first, bind after.
- `style.apply` replaces variables bound to what the style sets; editing a styled list unlinks the style; changing what a text style sets on linked chars unlinks them.
- A text style binds `fontSize`, `lineHeight`, `letterSpacing`, `fontFamily`, `fontStyle` (not weight).
- Variable ids are reused (highest plus one); node ids are not.
- Fonts are static instances where the font is: check `text.fonts {family}`; `text.missingFonts` lists what a file lacks.

**Components**
- Variants: one component per combination named `Prop=value, Prop=value`, then `component.combineVariants {ids}`; a name without `=` becomes `Property 1=Default`. Properties are keyed by display name and defined on each member; `component.properties {id}` on a set returns `{component, set, properties, conflicts}`.
- The default variant is the top-left member. Two members with one combination are listed as `conflicts`; the set never breaks.
- An instance is made with a copy of its main's layer data.

**Read-back**
- `node.get` lists children one level down whatever `depth` it gets (`depth: 0` lists none). Its command doc says `{id}`, the protocol doc `{id, depth?}`.
- **Not reported anywhere (measured, 0.9.0):** a layer's wiring to a component property (`component.bindProperty`) and a frame's explicit variable mode (`variable.setMode`). The request in `.reference/figcraft/request-node-get.md` still applies.
- `node.get` on an instance lists `componentProperties` for text, boolean and instance-swap properties only; variant values come from `component.properties` on the instance.

## The refused items and the untried commands, measured

All against app 0.9.0, 23 October 2026, in a new file. "Field" names below are FigCraft's.

### The four untried commands

**1. Per-side stroke weight bindings.** `variable.bind {ids, field: "strokeTopWeight" | "strokeRightWeight" | "strokeBottomWeight" | "strokeLeftWeight", variable}`.
- Read-back: `boundVariables: {strokeTopWeight: "VariableID:1", strokeLeftWeight: …}` and `strokeSides: [t, r, b, l]` with the bound values (`[2,1,1,2]`; `[5,1,1,5]` after `variable.setMode` to the mode holding 5). Binding a side turns individual strokes on. `strokeWeight` stays a scalar of its own.
- **Gotcha:** a literal side written after a side binding (`node.set {strokeRightWeight: 3}`) **detaches every side binding**, not only its own: `strokeSides` is one field to the detach rule. Literal sides first, then the bindings, keeps all of them (`[2,3,0,2]`, both bindings kept).
- `node.set {strokeWeight: 4}` after side bindings keeps `strokeSides` and the bindings (`strokeWeight` reads 4, the sides are unchanged). Binding `strokeWeight` does not reset the sides either.
- **`variable.bind` accepts any field name.** `field: "strokeBogusWeight"` answers `{ok: true}` and appears in `boundVariables`. A typo binds nothing and says nothing.
- **Toghen:** works, with one bug to fix. `fieldCommands` writes the sides in the order top, right, bottom, left, each bound or set. A literal side after a bound one loses the earlier bindings. Write the literal sides in one `node.set`, then bind.

**2. `component.editProperty {id, name, newName}`.**
- On a variant axis (`State` → `Status`): `component.properties` lists `Status`, the members are renamed (`Status=rest, Size=s`), and an instance's value stays (`hover`).
- On a text property (`Label` → `Caption`): renamed on every member's `componentPropertyDefinitions`; the instance's value follows (`componentProperties: {Caption: "Hi"}`).
- **Toghen:** works as written (`RENAME_AXIS`).

**3. `instance.setProperties` with an instance-swap value.** `{ids: [instance], properties: {Icon: <component id, a number>}}`.
- The swap property was made with `component.addProperty {id, name, type: "instanceSwap", default: <component id>, layer: <nested instance>}`.
- Read-back: `component.properties` on the instance gives `{name: "Icon", type: "instanceSwap", default: 12, value: 13, preferred: []}`. `node.get` gives `componentProperties: {Icon: 13}`, and the nested instance's `mainComponent: 13`.
- **A name is refused:** `Icon takes a component id`.
- **The nested instance is renamed** after its new main (`IconA` → `IconB`). A reconciler that addresses layers by name must expect it.
- `component.editProperty {name, preferred: [ids]}` sets preferred values (read back as `preferred: [12, 13]`).
- **Toghen:** works as written (`componentNamed` sends the id).

**4. `node.reparent {ids, parent, index}`.**
- Into another parent: `index` is the child-list position, 0 first (the first in an auto layout flow).
- Within the same parent, `index` counts the list **before** the moving layer is taken out. Moving down by one needs `index` + 2 of its old place: `[y,a,x,b,c]`, y to `index: 3`, gives `[a,x,y,b,c]`.
- `node.reorder {id, index}` takes the **final** index instead.
- An index past the end appends; there is no error.
- **Toghen:** `indexFor` (after's position + 1 in the current list, the moving layer included) gives the right result for both commands. Works.

## Headless and CI

**`figcraft-cli run <script> [--in f] [--out f]`** is a one-shot session, measured with CLI 0.7.0. The script is JSON, `{commands}` or JSONL, where `//` lines and blank lines are skipped.
- The whole script is one undo step and all-or-nothing, with `$step` references. It prints one JSON line per step once the script is through.
- **A failure prints only the failing line** (`{"ok": false, "error", "rolledBack": true}`), exits 1 and saves nothing. Reads earlier in a failing script are lost.
- Bad arguments exit 2; 27 ms for a small script.
- Reads work (`variable.list`, `node.get`), and so do writes and `--out`.
- **It cannot serve Toghen's run as it is.** The run reads, plans, writes, reads back receipts and writes stamps, and it walks layers one `node.get` level at a time. `run` would need one process per round, each re-opening and saving the file: possible as a slow replay, not as the target.

**`figcraft-cli mcp` (headless, stdio MCP)** is a long-lived in-process session with the app's command registry. Measured: `open_file {path}`, then `run_command doc.list`, a `batch` starting with `doc.switch {index: 1}` and holding a write and a `node.get`, then `save_file {path}`. All of it worked, and the saved file held the change.
- There is no `window.list` and no window; Toghen's target already handles "no window".
- **This is a CI route for `.figcraft` files:** Toghen's FigCraft target needs a second transport. It would send `tools/call run_command {command, params}` (or `batch`) over a child process's stdio instead of `engine.execute` over the socket, and open and save the file itself. The plans, view and writer are unchanged.
- It needs CLI ≥ 0.8.0 for `pluginData` in `node.get`: 0.7.0 does not report it, so stamps would read as absent.
- `--automation-read-root` / `--automation-write-root` confine it.
- `--no-system-fonts` (or `FIGCRAFT_NO_SYSTEM_FONTS=1`) makes renders the same on every machine, but it also changes what `text.fonts` lists, which the style plan reads. `text.loadFont {path}` (CLI ≥ 0.8.0) adds a font from the repository.

**Other CI uses:**
- `figcraft-cli info --json` for counts and missing fonts.
- `render` / `export --format png|svg|pdf` for picture checks of components.
- `export --format fig` (experimental) to hand a `.fig` to other tools.
- `variable.export {format: json|css}` / `variable.import` (the REST local-variables shape) as a variables-only route.

### With Toghen's docs

- **specs.md, *FigCraft*, *Not in this design*:** "Continuous integration has no plugin open. It could reach only variables, over REST, and only on Enterprise." That is true of Figma. For FigCraft files, headless `figcraft-cli mcp` gives CI the whole target (*Headless and CI*).
- **decisions.md, *Ruled: a FigCraft target*:** "Rejected: talking to FigCraft through `figcraft-cli mcp`". That was right for the live app. Headless is the one route where MCP is the only way in, so the ruling should name its scope.
- **specs.md:** "A property's description and preferred values are not written: … its preferred values take component ids, which an edit of the property does not carry yet." FigCraft's `component.editProperty {name, preferred: [ids]}` works (measured). The gap is Toghen's step, which carries no ids; FigCraft is not the limit. Property descriptions: `component.addProperty` has no description parameter, so that half stands.
- **specs.md, the list of what is refused:** most refused kinds and fields are now buildable with measured commands: effects, layout grids, constraints, dashes, grid layout and tracks, LINE, SLOT layers and properties, slot contents, gradients, and literal corners. Only partly buildable: blend (normal against pass-through cannot be read), line caps (not reported) and components named by key (no keys; local libraries by path and name only).
- **reference.md, the field writer:** "a token bound by `variable.bind` …", with corners "cornerRadius first: a corner then overrides its own" (code comment in `figcraftApply.ts`). Measured: a per-corner binding beside a bound `cornerRadius` does not override it; it is inert.
- **figcraftApply.ts per-side strokes:** the side order loses bindings when a literal side follows a bound one (measured).
- **Nothing contradicts** the stamps and components findings of 22–23 October (pluginData round-trips, ids, `node.get` one level deep, unreported wiring and modes): all reconfirmed on 0.9.0.

## Open questions

1. **Normal against pass-through** on frames: both read back without a `blend` key. Does FigCraft store them apart, and does `node.get` omit only the layer kind's default? It matters for a receipt of `blendMode` on containers.
2. **Line caps** (`strokeCap`, `startCap`, `endCap`) are accepted and not reported. Is that a reporting gap or are they ignored on `LINE`? Worth a render check.
3. **Pin 0.9.0 or 0.10.0?** Identical for agents; 0.10.0 is the release a fresh `brew install` gets. Whichever is chosen, the CLI cask in `egildo/apps` must move with it (≥ 0.8.0 for `pluginData`).
4. **`variable.bind` with an unknown field** is accepted and listed in `boundVariables`. Worth an upstream issue, beside the drafted `node.get` request (both are "a write that says nothing").
5. **Auto layout keys on instances:** 0.7.0 made `node.set` refuse auto layout keys off frames. Does an `INSTANCE` count as a frame for padding, gap and alignment overrides? The docs say an instance overrides padding, gap and alignment; not probed.
6. **A headless transport in Toghen:** wanted when a consumer asks to sync `.figcraft` files in CI. It needs the CLI at the app's version and a decision on fonts in CI.
